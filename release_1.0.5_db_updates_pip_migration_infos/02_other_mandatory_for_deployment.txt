Release 1.0.5 — mandatory deployment (non-SQL, non-pip)
=====================================================

Apply in order when promoting this release across environments (dev, staging, prod, etc.).

1) Code deploy
   - Pull/checkout tag or branch containing 1.0.5 API changes (FCM utils, mobile_agent routes, process_alarm).

2) pip install
   - See 01_pip_firebase_admin_mobile_agent.txt (install from api/app/requirements.txt).

3) Database
   - Run 01_mobile_agent_fcm_tables.sql on the target Postgres (once per environment).
   - Run 03_flattening_policies_and_job_workflows.sql (flattening policies + dispatch_flattening_refreshes workflow).
   - Run 04_data_lifecycle_and_job_workflows.sql (data_lifecycle_policy enums/table + lifecycle + purge_soft_deleted templates).
   - Canonical copies live under db-structure/update_old_db_flattening_policies_and_jobs.sql and update_old_db_data_lifecycle_and_jobs.sql.

4) Firebase / secrets
   - Place Firebase service account JSON on the server (not committed to git).
   - Set env: FIREBASE_CREDENTIALS_PATH=/absolute/path/to/adminsdk.json
   - Or use default path under repo: firebase-info/<your-adminsdk>.json (see api/app/utils/fcm.py).
   - Same Firebase project as the Android app’s google-services.json.

5) API restart
   - Restart the API process/worker after env + pip + SQL.

5b) Admin menus (Flattened Datas, Data Life Cycles)
   - Re-apply the Developer Console section of db-structure/noolvandb_feeds.sql on each DB, or insert the two menus manually for app_name=developer_console.

5c) Job workers
   - Workers must load new handlers: refresh_flattening_table, sync_lifecycle_table, purge_soft_deleted (restart job worker processes).

5d) Schedulers (optional)
   - Point a scheduler job at template dispatch_flattening_refreshes and/or dispatch_lifecycle_syncs when interval-based refresh is required.

6) Optional workflow
   - For broadcast FCM to mobile, ensure process_alarm job payload includes company_id when alarm_target is all_devices (see how-to-connect-websocket).

7) Mobile / QA
   - POST /api/register-device, GET /api/pending-tasks/{device_id}, trigger alarm, verify job result fcm_sent / pending_enqueued.

Notes
-----
- Roll out environments on your own schedule; this file is the checklist only.
- Do not commit service account JSON; use .gitignore and secrets store on each host.
